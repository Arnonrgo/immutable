Phase 4.2: List tail buffer (ADR-005), back-to-back A/B
=========================================================
toolchain: go1.27.4 darwin/arm64
date: 2026-11-17
load: average 165-175 on 10 cores (heavily loaded), so only interleaved
      comparisons are used (alternating old, new, new, old, ...). Every time is the
      minimum over 5 rounds of 100 ms. Allocation counts and bytes are exact.
      "ns" for the builds below is per whole build, not per element; B and
      allocs are per whole build too (divide by N for per-Append figures).

Change
  List keeps its last 0..32 values in tail []T outside the trie. Append copies
  the tail and the List (2 allocations) and touches the trie once per 32
  appends, when the full tail becomes a leaf. listSliceNode, toTrie and
  listSliceThreshold are removed. See memory-bank/ADRs/ADR-005-list-tail-buffer.md.

Method
  OLD = 4c9057b (ADR-005 commit, old List code) in a detached worktree plus the new
  Baseline_List_Small benchmark. NEW = working tree. Binaries built with
  `go test -c`, run alternately by /tmp/ab_queue.py.

Result against the ADR-005 model (T = int, N = 100,000, per Append)
  modelled   2,048 B -> about 262 B (7.8x)
  measured   1,863 B -> 256 B (7.3x), 4.69 -> 2.11 allocs, 52.5 ms -> 9.3 ms per
             100,000 Appends (5.6x). The measured old figure is the average over a
             build that starts small; the 2,048 B figure is the steady state at 100k.
  The plan's 4.7 gate asks for 10x fewer B/op for Append at N=100k. It is NOT met:
  7.3x. Reaching 10x needs ADR-005 option D (a shared tail with a CAS counter).

Reading the tables
  - Append: the headline. N=1,000: 3.0x time, 3.9x bytes; N=10,000: 4.5x, 5.9x;
    N=100,000: 5.6x, 7.3x.
  - Builder (ListBuilder.Append): 2.2-2.9x faster; at N=1,000 allocations fall
    from 100 to 39 (no more slice node conversion).
  - BatchBuilder and New: unchanged within noise (bytes +96 for the 32-slot tail
    copy plus the larger List; the 0.87-0.97x time rows are inside the noise of
    this machine, the same rows swing the other way between runs).
  - Get, AppendBuiltGet, Iterator, Contains, Prepend: unchanged within noise.
  - Set at N >= 1,000: +29-31 B/op (the List struct is 64 B, was 32 B) and one
    allocation fewer; ns within noise (0.88x-1.12x either way across rows).
  - Small lists: +8 B per list of up to 32 values (New N=1: 64 -> 72 B), one
    allocation fewer, no slowdown; Append onto 32 values 2,080 -> 360 B,
    onto 33 values 896 -> 80 B, New of 33 values 1,184 -> 360 B.

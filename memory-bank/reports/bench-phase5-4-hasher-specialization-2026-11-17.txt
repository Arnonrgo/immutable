Phase 5.4: choose the default hasher per key type in NewHasher
===========================================================
toolchain: go1.27.4 darwin/arm64 (Apple M1 Pro)
date: 2026-11-17
load: average 85-220 on 10 cores (heavily loaded). B/op and allocs/op are exact. Times
      are the minimum of 7 interleaved runs of 100 ms, old binary (the 5.3 string-hash
      commit b167e24) against new, so ratios under about 1.5x are not reliable
      individually; read the direction across rows, not one row.

Change
  defaultHasher[K] switched on the type of the key on every Hash call, and its Equal
  compared any(a) == any(b) (both keys boxed, compared by the runtime). NewHasher now
  picks the hasher once, from the type of the key: integerHasher[K] (hashUint64 of the
  sign-extended key, Equal is a == b) for the 11 built-in integer types and stringHasher
  for string. Named types (type ID int) still get the reflection-based hasher.
  Hash values are unchanged (TestIntegerHasherHashesLikeHashUint64, including the sign
  extension of negative keys), so no iteration order changes.

What the data says
  - Reads are faster in every group, with no row below 1.00x for Get, GetMiss or
    Small/GetHit: large-map Get 1.02-1.30x (seq keys 1.10-1.30x, where the hash is a
    larger share of the time), Map GetMiss 1.04-1.16x, MapString GetMiss 1.00-1.13x, string GetShuffled 1.03-1.13x,
    small-map GetHit 1.09-1.66x (int 1.09-1.66x, string 1.26-1.60x).
  - Writes are level: Set/SetOne/DeleteOne/SetLoop 0.96-1.11x with no direction,
    because allocation dominates them. B/op and allocs/op are identical on every row
    but one, which differs by 1 B (DeleteOne/seq/N100000, 1842 and 1841: rounding of an average).
  - Cost: none measured. NewHasher grows by 12 explicit cases, and the hashers are
    zero-size values, so a map holds the same two words as before.

Tests
  TestNewHasherIsChosenPerKeyType (every built-in type gets its own hasher, named types
  the reflection hasher), TestIntegerHasherHashesLikeHashUint64 (all 11 integer types,
  extremes, sign extension, Equal by value), TestDefaultHashersDoNotAllocate. The tests
  that built defaultHasher[int] directly (TestInternal_mapNode_*) use NewHasher(0).
